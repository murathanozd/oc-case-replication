## Answers to the R1 open points

**1. Def. 10 – global vs. any start/end events.** Same event (and object) sets in every case on the running example; only the recorded other-side events differ.
- Unfiltered start cases: global == any: True. (O1_*: e1 e18 e27 e28 e30; O2_*: e2 e5 e7 e9 e19 e20 e21 e27 e28 e30 e33 e34.)
- Unfiltered end cases: global == any: True. (*_O1: e1 e2 e3 e4 e5 e6 e7 e8 e10 e11 e18 e19 e20 e27 e28; *_O2: e2 e3 e4 e5 e6 e7 e8 e19 e20 e21 e33 e34.)
- Filtered start cases: global (full) == any: True; filtered end cases: global (filtered) == any: True.
- Reason: on this log every non-global end (start) event of an object lies on a df-path to (from) a global one, so the extra executions of "any" are contained in the global ones. This is a property of the data, not of Def. 10; R3 will show whether it holds on real logs.

**2. Def. 11 – global start/end events before vs. after filtering (A5).**
- Start case D[Order → ∗ \ SO] (Fig. 11): no difference (full == filtered: True); O_end is ['I1', 'I2', 'O1', 'O2', 'P1'] in both readings. O1_*: e1 e18 e27 e28 e30; O2_*: e2 e5 e7 e9 e30 e33 e34.
- End case D[∗ → Order \ SO] (Fig. 12): differs (full == filtered: False). O_start before filtering (full) = ['A', 'B', 'O1', 'O2', 'P1'], after (filtered) = ['O1', 'O2', 'P1', 'X1', 'X2', 'X3', 'Y1', 'Y2'].
  - before (full): *_O1: e1 e18 e27 e28; *_O2: e2 e5 e7 e33 e34;
  - after (filtered): *_O1: e1 e6 e10 e11 e18 e19 e20 e27 e28; *_O2: e2 e5 e6 e7 e8 e19 e21 e33 e34.
- R1 (the tutorial query) equals the **after** reading. The paper's text on Fig. 12 (both cases depend on the same Receive SO events) also fits only "after": e6 and e19 (Receive SO) are not in the "before" cases. "Before" gives e1 e18 e27 e28 for ∗→O1, as R1 predicted. In the "after" reading the projection brings back excluded behaviour (spurious and reintroduced df-edges, see `projection_check.md`).

**3. Def. 9 – self-pairs and "distinct types" (A3).**
- Without self-pairs (R1 query): 13 executions (Order -> Invoice 4, Order -> Order 1, Order -> Payment 2, Payment -> Invoice 2, Supplier Order -> Order 4).
- Def. 9 as written (self-pairs): 16 executions (Order -> Invoice 4, Order -> Order 3, Order -> Payment 2, Payment -> Invoice 2, Payment -> Payment 1, Supplier Order -> Order 4); the extra ones are O1_O1, O2_O2, P1_P1.
- "Distinct object types" literally: 12 executions (Order -> Invoice 4, Order -> Payment 2, Payment -> Invoice 2, Supplier Order -> Order 4); O2_O1 is dropped.
- Order→Order: 1 (query) / 3 (Def. 9) / 0 (distinct types). The by-object and by-type global restrictions (A4) give the same executions: True.
